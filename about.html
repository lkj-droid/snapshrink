About SnapShrink

Last updated: 27 November 2026

SnapShrink is a one-page utility for the tedious part of publishing images: getting them small enough, in the right format, and at the right dimensions — without handing a folder of personal photos to a stranger's server.

Why another image converter?

Search for “compress image” and nearly every result asks you to upload your files. That is fine for a stock photo and less fine for a passport scan, a receipt, a screenshot of a private chat, or the photos from a family event. Those services also tend to add watermarks, cap batch sizes, or slow you down with a queue.

The browser has been able to decode and re-encode images locally for years. SnapShrink is simply that capability arranged into a competent interface: batch input, format choice, a quality slider that updates real file sizes as you move it, resize presets for the platforms people actually publish to, and one ZIP at the end.

How it is built

  • No framework, no build step. Three static files — HTML, CSS and one JavaScript file — served from GitHub Pages.
  • Decoding uses createImageBitmap with the from-image orientation option, falling back to an <img> element. This is what applies EXIF rotation correctly.
  • Resizing draws onto a canvas with progressive halving, which keeps downscaled photographs sharp instead of soft.
  • Encoding uses canvas.toBlob() with the chosen MIME type and quality. WebP availability is detected at runtime, and the interface falls back to JPEG if a browser cannot produce it.
  • ZIP is written by about a hundred lines of JavaScript (CRC-32 plus stored entries), so there is no CDN, no external library, and nothing to break offline.
  • Privacy is a property of the architecture, not a policy: the page makes no requests after loading, apart from optional advertising if it is switched on.

What it does well

  • Screenshots, UI mockups and flat graphics: PNG to WebP at 80% typically saves 70–90%.
  • Phone photos for the web: resize to a 1920px maximum width and export WebP for fast pages.
  • Thumbnails and social images: the built-in platform presets (YouTube 1280×720, Instagram post and story, X 1600×900, link preview 1200×630, Pinterest 1000×1500, app icon 512×512) crop or fit to exact dimensions.
  • Checking a photo before it goes public: each card reports the EXIF tag count, camera, capture date and any GPS coordinates found in the header, and then confirms the converted file carries none of them.
  • Email and forms that only accept JPEG: convert and flatten transparency onto white in one step.

What it does not do

  • Animated GIF or animated WebP output — canvas encoding produces still images, so only the first frame is converted.
  • HEIC/HEIF input — browsers do not decode it in canvas. Export as JPEG from the Photos app first.
  • Metadata editing — SnapShrink reads and reports EXIF/GPS tags and drops them on convert, but individual tags cannot be rewritten. Watermarking and colour-profile conversion beyond the browser's default are out as well.
  • Server-side processing for extremely large files. Everything runs in your device's memory, which is both the privacy guarantee and the practical ceiling.

Who made it

SnapShrink is an independent side project, published openly so anyone can read the code, fork it, or host their own copy. The source lives at github.com/lkj-droid/snapshrink.
